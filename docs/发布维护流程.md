# 后续维护与发布

现行操作使用仓库技能[新仙剑打包与发布](../.agents/skills/newpal-release/SKILL.md)，可用`$newpal-release`调用。

1. 读取baseline、当前状态与Git差异，确定只更新玩家补丁/工具/文档/美术中的哪些；保留用户README版式。
2. 复用与输入哈希、方法版本、验证依赖一致的现有证据。只补受影响功能及新增/变化内容隐私检查；离线/实机/安装/公开分别记录。
3. 明确公开文件清单，更新源码、说明和状态摘要。凭据、存档、私人配置/原始日志/备份/旧包留公开树外。
4. 同一份成果只打一个固定ZIP，同时用于本地分享和GitHub；有同身份包就复用。`release_once.py`可记录证据与打包回执。包固定后不在上传步骤重建；内容变化用新候选/标签。
5. 固定公开清单、审阅差异并提交，向已确认仓库推送固定提交/标签；上传同一个已检查附件，不覆盖旧发布隐藏变化。
6. 远端核对分支/标签提交及附件SHA256/大小。服务端无可靠digest、不一致或需下载链验证时才回下载一次；一般不逐blob重新下载源码。
7. 一次同步工作记录、当前状态、分享入口和发布回执。公开文档用标签，本地回执记精确提交，避免纯粹回填哈希导致新一轮提交/重打包。

回流用Issue/PR说明基线、问题、改动、证据和未测项，不自动执行未知来件。新发布仍需用户授权；skill不扩大权限。隐私边界见[维护与隐私](维护与隐私.md)，不能只看“无命中”就忽略二进制内嵌内容。历史首次整理脚本不要重跑覆盖首页。
