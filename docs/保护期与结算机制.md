# 保护期交互与统一结算消息

当前精确目标见baseline.json。以下为当前源码契约，不把旧试验的推测当原生事实。地址为受支持映像下的VA，使用前仍须校验输入字节。

## 保护不等于禁用所有交互

`encounter_object_split_v1.py`区分敌人与非敌对象：对象0x2000标记与四个原有保护判定点配合，宝箱/NPC/开关沿原交互执行；敌人或无法确认的对象保留保护。`encounter_manual_reentry_v1.py`仅放行第1/3道主动操作路径，第2/4道仍阻止保护期内的被动碰撞。

复用原生意图判定：第1道在0x45D390附近观察操作边沿；第3道沿0x493562—0x4935A2短按及距离规则（原生100ms分支）。没有另加按下/松开钩子，也没有统一250ms新规则。不要通过全清计时器、全开对象标志来实现手动遇敌，否则碰撞保护和其他交互会一并失效。十里香/设置机制保持既有条件。

## 跳过显示，不跳过奖励

原生文字绘制入口0x49FC60、消息队列0x53E690、结算状态0x599814。旧公开修正只覆盖升级/学技能两类，遗漏了经验/物品等消息；当前`settle_message_skip_v5.py`在统一消息链缩短当前消息的显示截止时间，仍由原程序移除队列和推进结算。

状态1—5按次提前到期（逃跑在状态2）；6—12需维持到期锁存直到原生消息移除。状态0复位，超过12不操作。原生输入观察值产生新按下边沿，支持左键、空格、回车/小键盘回车、A/B；一直按住不是每帧的新按下。不要把奖励循环直接跳转到结束，也不要用全局键盘/鼠标钩子覆盖剧情等待。

用户确认战后经验、物品、属性、升级等消息可跳过。各状态分支有离线边界证据，但不能据此承诺所有硬件和特殊剧情已遍历。

## 鼠标尚未解决的部分

v5保留既有首帧系统鼠标处理；启动双鼠标/等待光标仍有反馈。原生光标可能在后续弹窗下方。v6/v7置顶实验引发双鼠标或闪烁，已撤回，不在本发布目标中；v5内未挂接的cursor_late辅助代码不代表启用置顶。后续应独立验证真正呈现链、可见性和生命周期，避免用菜单处理函数代替最终绘制出口。
