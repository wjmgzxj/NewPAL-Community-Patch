# 构建与验证

当前提供两种不同的证据，不混为一谈。

## 精确重建最新补丁

需要Python3.10或以上的标准库与自己的受支持Steam原版EXE。命令在仓库根目录运行：

```powershell
py -3 tools/build_current.py --original "原版EXE的路径" --output ".local/reconstructed"
```

输出目录必须为空且不得是原游戏目录；工具先核对原版、差分、目标和资源哈希，再输出最新EXE及119图。它不登录Steam、不判断购买所有权、不启动游戏、不安装、不碰存档。

此方式重放冻结差分，用于不依赖维护者私人备份得到完全相同的当前基线，**不是从全部功能源码重新编译EXE**。差分与生成工具一起维护，发生功能变化后必须更新并再次验证。

## 从源码核对地图运行代码

安装requirements-map.txt所列依赖，用`tools/verify_map_source.py --exe .local/reconstructed/NewPAL_Release.exe`核对当前地图代码生成器与候选内机器码。该工具只读输入，生成的代码留在内存用于比较，不写游戏。

源码库中的旧验证脚本按各自精确历史输入设计，不能全部直接对最新EXE运行。离线x86执行需要Unicorn等额外依赖与正确夹具；缺失前置时写未验证，不把错误夹具当成游戏故障。

## 必要回归

剧情速度：梦境怪物/主角飞行正常，荷花运输正常，普通地图小怪巡逻/追击仍减速。输入：键盘/手柄连续移动及鼠标干扰、地图关闭/跨场景。地图：人物所在路段、层切换、途中揭雾、片区名显隐、存档回滚和旧探索迁移。补丁：文件清单齐全、原版一次安装、重复操作、缺图和还原。

仅跑受影响的检查，保留输入哈希与报告。离线通过、成功瞬移和用户实际游玩是不同证据；公布准确待测范围。

## 从源码重建本轮三项新增

提供原版EXE与已安装MSVC的x86工具目录（含cl.exe/link.exe）：

```powershell
py -3 tools/build_updated_from_source.py --original "原版EXE的路径" --msvc-tools "MSVC的bin/Hostx64/x86目录" --output ".local/source-built"
py -3 tools/verify_gu_runtime.py --built ".local/source-built"
```

第二步另需Unicorn。第一步先从用户原版重建冻结v0.3.0基线，再执行原生恢复v2、提示跳过v1及编译炼蛊v6；输出须精确匹配baseline.json。旧基线差分仅为研发依赖，不是推荐安装旧版的入口。此流程无私人备份/测试存档依赖，不安装或启动游戏。

公开回归为54类本机检查的可携带子集；执行原生选择/显隐/合拢及事务边界，图形、库存等有替身。更多契约见[炼蛊与战后机制](炼蛊与战后机制.md)。
